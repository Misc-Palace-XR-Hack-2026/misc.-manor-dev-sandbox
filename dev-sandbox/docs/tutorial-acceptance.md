## Architecture and preservation

Existing software: one Store, shared `LESSONS`/onboarding reducer, desktop TutorialView/MenuView/RoomView, XR canvas guide and command panel, importer, per-room local storage with backup, Undo, content creation, safe pickup cancellation, themes and surface controls.

New software: `Store.beginPractice/endPractice` retain the personal state, history, pickup, selection, visit state, save error and original room identity by reference. Practice starts with new sample state and independent history. All practice saves are suppressed, room navigation uses disposable practice rooms (never reads another personal save), and the active-room preference is untouched. Exit/completion/replay restores references without calling a saving mutation. Reload discards practice and loads the unchanged personal save; onboarding status is stored separately. No tutorial snapshot is written into a personal room. Async file/photo/surface work captures a session epoch; entry, replay, exit and every room switch invalidate it, including round trips. Content-editor drafts close on session change.

Shared action steps consume observed state transitions for creation, placement, movement, storage, restoration, room return, lighting, surfaces and Undo. Control events cover opening panels and validated input. Opening Inbox does not claim restoration. Wrong-object movement does not satisfy the practice-object step. `Show control` recovers closed panels; Restart, Skip/Exit and Help's lesson picker are available. Highlights track actual DOM controls and projected scene pads each frame; the scene practice object has an outline. They do not intercept input. Reduced-motion avoids highlight shadows; instructions never require audio.

## PR #82 integration constraints

Likely conflicts: Store (new mode guards vs practice lifecycle), MenuView (mode chrome, async guards, sheet lifecycle, row actions), TutorialView (mode checks vs practice runner), content editor (Preview draft cancellation vs epoch cancellation), RoomView (VR entry restrictions vs scene cues), CSS and browser tests. No Preview feature or patch from #82 is included here.

Integrate only after preserving both invariants: mode restrictions apply within whichever state session is active; practice never writes personal storage. Before entering Preview during practice, explicitly exit or pause the isolated session without calling `replaceState` on personal content. A stale async task must satisfy both the mode-generation guard and the practice/room epoch guard; returning to Edit must not revive old work. Keep room navigation's practice branch separate from persistent active-room preference writes. Combine editor subscriptions so either mode or epoch transition invalidates a draft. Verify Help/guide behavior in Preview and Edit, preservation of personal history/pickup, all-room storage comparison, delayed work across Preview→Edit and practice→personal, desktop/mobile highlight geometry, and XR entry boundary. Re-run both PR #82's interaction-mode suite and this tutorial suite. Never restore the old snapshot-through-save tutorial implementation while resolving conflicts.
